# Full-surface audit — deutsch-meister.de (2026-08-16)

Six parallel audits (database, rendered HTML, Netlify functions, SPA code, conversion/UX,
performance) plus direct production inspection via the Supabase, Netlify and Resend APIs.
Every finding below carries evidence — SQL and its result, `file:line` with the code, or a
measured number. Claims that did not survive verification were dropped and are listed at
the end.

**Nothing in this document has been changed.** It is a findings report.

---

## P0 — Actively costing money or blocking the funnel

### A-01 · The free tier renders a permanent spinner for logged-out visitors
`src/components/onboarding/OnboardingGate.jsx:8` returns a spinner while `!profileLoaded`.
`src/hooks/useOnboarding.js:14-19` sets `profileLoaded = false` and returns early when there
is no user — so it is **never** set true for an anonymous visitor.

Verified chain for `/level/a1.1` while logged out:
`LevelSubscriptionGuard` → `isLevelFree('a1.1')` is true → returns children with no auth check
(`LevelSubscriptionGuard.jsx:16-18`, `src/config/freeTier.js`) → `EmailVerificationGate` passes
through (`user && !isEmailVerified` is false) → **`OnboardingGate` spins forever**
(`src/App.jsx:170-181`).

Affects `/level/a1.1` (the navbar's "A1.1 Free" CTA), `/grammar/a1.1/:topic`, `/reading/a1.1`,
`/listening/a1.1` — the entire free sample. Present since the onboarding feature landed
(commit `0763334`, 2026-05-28); confirmed the same nesting existed before PR #13, so this is
not a regression from the recent audit work.

**Fix:** in `OnboardingGate`, `if (!user) return children;` — or set `profileLoaded(true)` in
the `!user` branch of the hook.

### A-02 · `analyze-sentence` is an unauthenticated, unmetered Claude endpoint
`netlify/functions/analyze-sentence.mjs:79-100` — `countTodayUsage` returns `0` when the
request has neither a user id nor an `anonymousId`, so `usedToday >= limit` is never true
(`:156-158`). No JWT and no `anonymousId` = unlimited.

Cost: `claude-sonnet-4`, `max_tokens: 1024` ≈ $0.016/call → **~$290/hour at 5 req/s,
~$1,150/hour at 20 req/s**. Production already contains one `xray_usage` row with both ids
null, so the path is reachable.

**Fix:** reject when both are absent, or key the quota on a hashed
`x-nf-client-connection-ip`; add an IP ceiling regardless, since the client id is forgeable.

### A-03 · `evaluate-speaking` has no rate limit and accepts a 1 MB attacker-supplied prompt
`netlify/functions/evaluate-speaking.mjs:158-197, 232-271`. Any signed-in user can POST an
arbitrary `session_token` (no session row required); with no stored transcript the handler
falls back to client-supplied `messages` — up to 200 × 5,000 chars — and feeds them to
`claude-sonnet-4-6`. ≈$0.75–1.50/call, doubled by the retry at `:269`. No per-user, per-session
or per-day cap exists. The same fallback is a direct prompt-injection path into the grader.

**Fix:** require the token to resolve to a session owned by the caller before any model call;
delete the client-transcript fallback; add a per-user daily cap.

### A-04 · `speaking_usage` is world-writable (RLS policy grants ALL to PUBLIC)
Verified directly: the policy named "Service role full access" has `polroles = {0}` — i.e.
PUBLIC, not `service_role` — with `cmd = ALL`, `qual = true`, `with_check = true`.

Any visitor can run `supabase.from('speaking_usage').delete().neq('id', …)` from the browser
console and wipe every quota row for every user, after which `checkUsage()` returns
`allowed: true` indefinitely (`netlify/functions/_shared/speakingUsage.mjs:46-57, 96-110`).
It also exposes every user's session timestamps.

**Fix:** `DROP POLICY "Service role full access" ON speaking_usage;` — the service role
bypasses RLS, so no replacement is needed (same shape as `webhook_logs`).

### A-05 · Speaking sessions are client-forgeable, so paid AI is free
Live RLS grants `authenticated` INSERT `WITH CHECK (user_id = auth.uid())` and UPDATE
`USING (user_id = auth.uid())` **with no `WITH CHECK`** on `speaking_sessions`.
`netlify/functions/speaking-turn.mjs:66-89` authorizes a turn purely on the row existing, and
never verifies it was created by `speaking-session.mjs` (which is where the wallet debit
happens at `:243-258`).

A user can insert their own `status:'active'` row and loop `/api/speaking/speaking-turn`
(OpenAI STT + Haiku + OpenAI TTS per turn) with no debit, no trial counter, no subscriber
check. The missing `WITH CHECK` on UPDATE also lets them reset `started_at` forever.
The SPA only ever *reads* these tables, so dropping the write policies breaks nothing.
Same applies to `speaking_messages` / `speaking_evaluations` (a user can write their own
perfect score).

### A-06 · `send-daily-test` is a public, unauthenticated email trigger
`netlify/functions/send-daily-test.mjs:97-127` gates the `?email=` parameter behind
`CAMPAIGN_SECRET` but leaves the **no-parameter** case ungated. `while true; do curl
https://deutsch-meister.de/api/send-daily-test; done` sends one Resend email per request from
`zaid@deutsch-meister.de` — quota burn, mailbombed inbox, and sending-domain reputation damage
that takes the real welcome and daily-sentence mail down with it.

### A-07 · A bounce storm on the shared Resend account is collapsing email confirmations
Signup → confirmation rate by month: **91% (Mar) · 82% (Apr) · 49% (May) · 71% (Jun) ·
60% (Jul) · 34% (Aug)**. Two-thirds of August signups never confirm, so they never reach the
product.

Cause, from the Resend API: **84 of the last 100 emails on the account are hard bounces to a
single dead address** (`a831969a52@emailinbo.live`), two every 15 minutes around the clock
(~190/day). Those are MedMeister sends, but both projects share one Resend account, and
DeutschMeister's "Confirm your DeutschMeister account" mail was observed going out through
the same account. SES suspends senders above ~10% bounce rate; this account is at ~84%.

**Fix (highest value per minute of work):** stop the job sending to that address.

### A-08 · Every "focus on this topic" link from the level test is dead
`src/data/levelTestQuestions.json` — all 80 questions carry `relatedTopicUrl`, rendered as real
navigation in `src/components/LevelTest/LevelTestResults.jsx:364-371, 417-425`.
71 use `/grammar/a1-1/…` (hyphen, where the app uses `a1.1` → "Topic not found"),
5 use `/vocabulary/…` (no such route → 404), 4 use `/reading/a1` (not a sub-level).
This is the highest-intent CTA in the funnel and none of it lands.

### A-09 · Paid content for all 8 levels is readable with the public anon key
`words`, `sentences`, `paragraphs`, `podcasts`, `grammar_topics`, `grammar_rules`,
`grammar_examples`, `grammar_exercises` all have `SELECT USING (true)` for `anon`. Only
`reading_lessons` / `listening_*` were narrowed by
`migrations/2026-08-16-fix-rls-security.sql:137-170`. The anon key ships in the bundle and
gating for these tables is purely client-side, so B2.2 vocabulary, sentences, podcasts and
every grammar lesson body can be dumped with one request.

### A-10 · The Impressum is published as an unfilled legal draft
`astro-site/dist/impressum/index.html` renders *"Entwurf: Die mit [ ] markierten Angaben
müssen vor Veröffentlichung vom Betreiber ergänzt werden"* followed by
`[Vollständiger Name des Betreibers]`, `[Straße und Hausnummer]`, `[PLZ und Ort]`, `[Land]`.
Every page footer links to it. German §5 DDG requires real operator data.

## P1 — Revenue, correctness and trust

### B-01 · Three accounts have Pro access with no valid subscription
`is_subscribed = false` is written in exactly one place — `lemonsqueezy-webhook.mjs:517`,
inside the `subscription_expired` handler. Nothing clears it on `cancelled`, `past_due` or
`unpaid`. Currently entitled without an active subscription:
`expired` since 2026-08-11, `unpaid`, and `past_due`. That is 43% of the paying base unbilled.
No leak in the other direction (0 active subs with the flag false).

### B-02 · Listening exercises are passable without listening — 83.7% of answers are "b"
Verified: of 399 multiple-choice questions, **334 are "b"**, 58 "c", 7 "a"; of 81 true/false,
71 are "Falsch". The keys are factually *correct* — the option ordering is what's broken.
Always choosing "b" scores 83.7% on every listening exercise at every level.
**Fix:** permute each question's `options` array and re-letter, updating `correct_answer`.
Grammar multiple-choice has a milder version of the same skew (48% option 0).

### B-03 · Every b1.2 reading lesson exists twice
Verified: `b1.2` has **16 rows but only 8 distinct `content_de`** — the seeder ran twice on
2026-02-03 (15:18 and 20:09), same `order_index` on both copies. Learners see each lesson
listed twice and per-level progress denominators are doubled. There is no unique constraint on
`reading_lessons` beyond the PK.

### B-04 · Podcast transcripts are 100% empty, but FAQ structured data claims they exist
All 24 podcasts have `transcript_de`, `transcript_en` and `vocabulary` NULL. Meanwhile
`src/pages/PodcastsPage.jsx:116` ships FAQPage JSON-LD answering *"Do the podcasts have
transcripts?"* with *"Yes, every podcast episode includes a full transcript in German with
translations"*. A Google-indexed rich result asserting a feature that exists for zero episodes.

### B-05 · All 64 grammar topic descriptions are punctuation-stripped in the DB
The Astro build reads `grammar_topics.description_en`; all 64 lack terminal punctuation and 56
differ from the correct copy in `src/data/grammarTopics.js` — commas stripped.
Shipped: `Understand grammatical gender (der die das) and noun patterns` ·
`Master ich du er sie es wir ihr sie`. This leaks into `<meta name="description">` and
`og:description` on 52+ topic pages and into visible copy on the 8 level hubs and `/grammar/`.
**Fix:** re-seed from `src/data/grammarTopics.js`, which has the good copy.

### B-06 · Logging in deletes the only link to Listening and Reading
`src/components/Navbar.jsx:100-110` (and `:324-336` mobile) wraps the `/level/a1.1` pill in
`{!user && …}`. Listening (480 dialogues) and reading (74 lessons) live as tabs inside
`/level/:level`, so a logged-in user has no click path to either. `user_reading_progress` has
**zero rows, ever**. The dashboard links neither, and the streak calculation
(`src/services/dashboardStats.js`) queries only grammar, X-Ray and speaking — so a week of
daily listening still shows a 0-day streak.

### B-07 · The whole post-signup experience is in German; acquisition is in English
Verified strings: `VerifyEmailPage.jsx` *"Bestätige deine E-Mail"*, `WelcomeModal.jsx`
*"Willkommen bei DeutschMeister"*, `IntroSlides.jsx` *"Einstufungstest starten"*,
`DashboardPage.jsx` *"Guten Morgen"*, plus `SentenceXRay.jsx` (the paywall),
`SubscriptionPage.jsx`, `SpeakingSession.jsx`, `SessionTimeoutModal.jsx`, `ProfilePage.jsx`.
The English text already exists in `{/* EN: … */}` comments beside several of them.
German backend error strings also surface verbatim in the English UI
(`speaking-session.mjs:248` → `SpeakingPage.jsx:446`).

### B-08 · There is no conversion mechanism
The trial takes no card (`LockedContentOverlay.jsx:38`), and the only checkout path is
`window.open(checkoutUrl, '_blank')` (`PricingPage.jsx:108`, `SubscriptionPage.jsx:70`,
`pricing.astro:236`) — blocked by iOS Safari and in-app browsers, which the codebase already
detects elsewhere (`SpeakingPage.jsx:65`). `SubscriptionPage` then polls 60 s and gives up
silently. There is no trial-day-3, day-6 or day-8 email anywhere in `netlify/functions/`.

### B-09 · Grammar lesson progress silently fails to save on re-submission
`src/pages/GrammarLessonPage.jsx:810-820` upserts `user_grammar_progress` **without
`onConflict`**, so PostgREST targets the primary key and the second attempt violates
`UNIQUE(user_id, topic_id)`. supabase-js resolves rather than throws, the returned `{ error }`
is never inspected, and the user sees "saved". The correct call exists at
`src/services/grammarService.js:551-553`.

### B-10 · The post-checkout page tells paying customers their payment failed
`src/pages/SubscriptionSuccessPage.jsx:14-43` — `hasActiveSubscription` is captured in a `[]`
dependency array and closes over the mount-time `subscription = null`, so it never observes
the refresh. Every purchase exhausts 5 attempts and falls to the un-verified branch.

### B-11 · `?tab=` is ignored, so podcasts are unreachable from the podcasts page
`src/pages/LevelPage.jsx:39` hard-codes `useState('vocabulary')` with no `useSearchParams`.
Callers that rely on it: `PodcastsPage.jsx:222` (every episode row),
`scripts/prerender-spa-routes.mjs:273` (the prerendered "Start Listening" CTA),
`VocabularySectionPage.jsx:88`. All land on the vocabulary tab.

### B-12 · Speaking missions exist only for A1.1
`speaking_missions` has 8 published rows, all `A1.1`; no other level has any.
`SpeakingPage.jsx:172` filters `.eq('level', selectedLevel)`, so learners at A1.2 and above get
an empty mission list with no explanation.

### B-13 · 94% of speaking conversations have no session row
242 distinct `session_token`s in `speaking_messages`, only 18 in `speaking_sessions`;
3,752 of 3,990 messages and 153 of 162 evaluations are orphaned. Sessions only start
2026-07-16 (mission mode). `evaluated` is false on all 18 rows despite 162 evaluations, and
`cost_cents` sums to 0 — per-session cost is never recorded. Also:
`speaking_sessions_level_check` rejects `'placement'`, which `speaking-session.mjs:175` passes
for the level test, so **every placement session 500s after paying for a Haiku completion and
a TTS render** (`:220-237` run before the insert at `:262`). Zero placement rows exist.

### B-14 · Production users are shown a database debug panel
`src/pages/LevelPage.jsx:357-368` and `:388-399`, not gated on `import.meta.env.DEV`, render
*"No vocabulary from Supabase / Table: words WHERE level = 'a1.1' / … missing RLS SELECT
policy, no data for this level, or column name mismatch"* — on the default tab of the free
A1.1 page.

### B-15 · 852 internal links 301-redirect, on every page
`scripts/prerender-spa-routes.mjs:346-348` canonicalises prerendered SPA routes to the
**trailing-slash** form and `public/sitemap-spa.xml` matches, but the Astro header/footer link
to the **non-slash** form: `/level-test` ×255, `/analyze` ×252, `/podcasts` ×166,
`/pricing` ×91, `/speaking` ×87. This also contradicts `CLAUDE.md`'s stated rule. Every page's
primary CTAs redirect. Pick one form.

### B-16 · Orphaned pages and FAQ markup with no visible content
`leitfaden/telc-b1/` (2,032 words, the site's second-longest page) has **zero inbound links**;
`reading/` has zero; `listening/` has one, from the orphaned guide. `/grammar/overview` has no
inbound link and is in neither sitemap.
Separately, `level-test/` and `podcasts/` ship `FAQPage` JSON-LD whose Q&A appear **nowhere**
in the rendered HTML — a structured-data policy violation and manual-action risk. Both are
indexable and in the sitemap.

  pages; 9 pages declare `lang="de"` while rendering majority-English content; 7 declare

- **`localStorage`/`sessionStorage` without try/catch** in three always-mounted components
  (`TrialBanner.jsx:13`, `ProgressContext.jsx:45`, and `ErrorBoundary.jsx:32` — the last-resort
  handler can itself throw). Private-mode visitors get the error screen.
- **Dead code:** `src/pages/PricingPage.jsx` (443 lines, unreachable — every pricing link is a

  homepage showing both "1,400+ Learners" and "350+ Learners", stats stamped "Stand: Mai 2026",
  and a "German German Noun Genders" duplicated-word bug on the homepage.

## P3 — Performance (and a correction to the previous baseline)

**The previously reported "mobile perf 62, ~477 KiB unused JS" was a measurement artifact.**
`scripts/lighthouse-batch.mjs` serves `dist/` without `Content-Encoding`, so Lighthouse scored
uncompressed bytes. Measured against a gzip server:

| Page | Mobile | Desktop | Mobile LCP |
|---|---|---|---|
| `/` (Astro) | **100** | 100 | 905 ms |
| `/pricing/` | **100** | 100 | 902 ms |
| `/grammar/a1.1/nouns-gender/` | **100** | 100 | 1054 ms |
| `/app.html` (SPA shell) | **94** | 100 | 2475 ms |
| `/level-test` | **92** | 100 | 2942 ms |

The Astro site is genuinely excellent. All remaining debt is in the SPA entry path.
Fix the harness first (gzip in the `createServer` handler) or every future audit chases a
phantom 30-point deficit.

Highest-value SPA wins, measured by building the change:

1. **Defer `posthog-js`** — it is `191,247 B` (51.4%) of the entry chunk, statically imported
   at `src/lib/analytics.js:1`, and cannot run without consent. Making it a dynamic import
   inside the post-consent branch measured: entry chunk **372,045 → 181,862 B raw**
   (−53% gzip), `/app.html` mobile 94 → **97**, FCP −370 ms, LCP −284 ms, transfer −61 KiB.
2. **Defer the Supabase client** — `172,523 B` eager, 83% measured unused; `realtime-js`
   (35,553 B), `storage-js` (23,207 B, one admin-only call site), `iceberg-js` and
   `functions-js` have zero application usage.
3. **Drop Fira Code** — 2 faces fetched on all 92 pages; `font-accent` appears 0 times in
   `src/` and the family is absent from the built CSS. The SPA also issues two separate Google
   Fonts requests (5 families / 20 faces) with different Cormorant weights than Astro's, so
   crossing from `/pricing/` to `/dashboard` re-downloads it.
4. **Lazy-load `content.js` + `grammarTopics.js`** from `ProgressContext` (42,066 B eager).
5. `IntroSlides.jsx` can never code-split (build warns on every build) because
   `OnboardingGate` statically imports it — 3,902 B stranded in the entry chunk.
6. Add a `[[headers]]` rule for unhashed root assets (`/consent.js` is `defer`-loaded on all
   92 pages with `max-age=0`); delete 48,430 B of unreferenced files (`logo.webp`,
   `og-image.webp`, `podcast-cover.svg`, `podcast-cover-template.html`); regenerate the
   800×800 / 70,930 B `logo.png` at 180×180.

**Do not** "fix" `manualChunks` — removing `vendor-ui`/`vendor-supabase` was tested and made
the entry chunk 26% *worse* (Rollup hoists shared vendors into the entry).

## Checked and cleared — explicitly not issues

Referential integrity is intact across every content and progress table (zero orphans, zero
duplicate topic slugs, zero `related_slugs` pointing at nothing). Level-case conventions are
respected in every table including the `reading_lessons` lowercase exception. No mojibake, no
placeholder text, no markup leaks, no `http://` links, no broken internal links, no missing
local assets, no duplicate titles or descriptions, no JSON-LD parse failures — across all 92
built pages. All 159 `webhook_logs` rows processed with no errors. Grammar exercise answer keys
are structurally sound (0 of 672 missing or absent from their options). The listening
`correct_answer: "b"` vs `options: "b) 17:00"` shape is an intentional letter-key convention
that works. `listening_exercises.status = 'completed'` on all 48 is harmless — nothing filters
on it. The welcome-email trigger is live and enabled on `auth.users`. No third-party script
executes before consent (Google Fonts is the one unconditional third party). Zero `<img>` tags
exist in the build, so there are no image-optimization findings. The SPA↔netlify.toml route
allow-list has no drift in either direction.

Two claims were **retracted** during verification: the daily-sentence blast is not being
truncated at 30 s (Resend shows ≥102 sends over 40 s at 0.39 s each this morning — the
underlying concern that 1,004 recipients take ~6.5 minutes still stands), and a reported gap
between key vocabulary and lesson text was an artifact of a stem match failing on plural
suffixes.
