# Course v2 — E1 server track (AI grading, entitlement, allowance)

**Date:** 2026-09-27 · **Status:** built and integration-verified. The E1 server track has two parts:
- the grading agent: writing, micro-outputs, speaking and the rubric registry → server;
- the entitlement agent: access rule, AI allowance, completion and migration.

This page says what exists, how to run it, what the integration pass changed, and what is still missing before
any level is sold as v2.
**Binding documents:** BLUEPRINT §1.5, §1.6, §4.2–§4.7; SCHEMA §2, §4.5, §8, §14. The entitlement details and the
owner SQL are in `ENTITLEMENT.md`; this page does not repeat them.

---

## 1. What exists

### 1.1 Request flow

```
client ──POST { taskKey, text }──────────────► evaluate-writing ──BANK_KEY_RE?──► rubrics/writingV2.mjs
client ──POST { courseTaskKey, minutes }─────► speaking-session ──v2 key?───────► startCourseV2Session
client ──POST { session_token, message }─────► speaking-turn     (task reloaded from the row every turn)
client ──POST { session_token }──────────────► evaluate-speaking ──key from row─► rubrics/speakingV2.mjs
                                                    │
        rubrics/data.mjs ── <level>.banks.json (compile.mjs) + rubrics.json (compile-rubrics.mjs)
        rubrics/courseAi.mjs ── _shared/entitlement.mjs (access · slot allowance · daily cap · ledger)
        rubrics/grade.mjs  ── profile → plan → prompt → model levels → rules.mjs → server totals
```

### 1.2 Files

| File | What it does |
|---|---|
| `netlify/functions/evaluate-writing.mjs` | Routes bank keys (`taskKey`/`task_key`) to the v2 branch before any legacy lookup. `courseTaskKeyPrefix()` answers for v2 keys; `courseAllowanceFor()` is 0 for them. The legacy tier counts leave out every v2 row. |
| `_shared/rubrics/writingV2.mjs` | v2 writing and written micro-outputs. Loads the task from the bank, never from client text. Refusals: speaking keys and spoken micro-outputs → 400, `deterministic` profiles → 400, missing profile or unknown rule → 503 `rubric_unavailable`, gate (§1.3). First attempt: self-correction hints only. Stores a `writing_submissions` row and records one use only after a real model call. |
| `_shared/rubrics/grade.mjs` | Builds the prompt from the profile: criteria, allowed levels, **descriptors**, spelling policy, **error policy**, feedback language. The model returns levels and flags; the server snaps each level (ties go down), applies the rules and computes every total. Aussprache is never scored (§3). |
| `_shared/rubrics/rules.mjs` | The 16 rule ids the registry names, no more and no fewer (Goethe E rules, `form-number-exact`, telc topic/situation, criterion I Leitpunkt caps, criterion II Textsorte/register/unconnected/Ich-Wir caps). Rules that need no model run first; a zero they decide costs no model call and no attempt. All rules run again after the model and always win (EXM-08). |
| `_shared/rubrics/speakingV2.mjs`, `_shared/speakingAI.mjs` | Parses and validates the key, loads the SpeakingTask, turns a spoken micro-output into a one-turn Sie monologue, and builds `buildCoursePartnerPrompt` (mode, role, du/Sie, fading support, cards; no corrections, no scoring, no answers about the course content). Grades a stored session once and stores the result in `speaking_evaluations` with `passed: null`. |
| `speaking-session.mjs`, `speaking-turn.mjs`, `evaluate-speaking.mjs` | The v2 branches. The session row stores only `topic` and `scenario = {v:2, courseTaskKey}`. A v2 session lasts 10 or 15 minutes, never 5, costs 0, and records one use per session. |
| `_shared/rubrics/{data,keys,defaults,courseAi}.mjs` | Runtime loader (four candidate directories), key helpers, model pins, and the entitlement → HTTP mapping (403 / 429 / 503). |
| `_shared/entitlement.mjs`, `_shared/courseV2Config.mjs` | `hasCourseAccess`, `courseAccess`, `checkCourseAiAllowance`, `recordCourseAiUse`. Details in `ENTITLEMENT.md`. |
| `_shared/speakingUsage.mjs`, `score-readaloud.mjs` | Course routing for `checkUsage`/`incrementUsage` (`{ courseTaskKey }`). v2 read-aloud lines are gated by course access. |
| `_shared/course-v2/rubrics.json` | Generated by `scripts/course-v2/compile-rubrics.mjs` from the rubric registry and `grammar-spine.json`. Do not edit it by hand. |
| `migrations/2026-10-01-course-v2.sql` | `course_ai_usage`, `exam_practice_results`, `learner_goals`, and the widened `review_cards.kind` and `lesson_progress.status` checks. The owner applies it by hand. |
| `src/config/courseV2.js` | `COURSE_V2_LIVE = []` and `V2_TRIAL_PRO_OPENS_PAID = false`. The routes agent owns it; it was created here only so the SPA builds. |

### 1.3 Response and gate contract

- **Gate** (`checkCourseAiAllowance`):
  - no purchase, unknown key or no user → **403** `course_access_required`
  - lookup failure → **503** `entitlement_unavailable`
  - slot or daily cap used up → **429** `limit_reached`
  - allowance per slot: Aufgabe 3, micro-output 2, Plateau/Halbtest/Modelltest part 2, Diagnose 1; daily cap 25. The slot is the bank key without its lane suffix.
- **Writing response:** the legacy shape plus these fields:
  - `schema: 2`, `scoreLabelDe: 'automatisierte Übungsbewertung'`, `noticeDe` (the §1.6 line)
  - `rubric` `{ id, max, examMax, … }`
  - `criteria[]`: scored entries carry `scored: true`; not-auto-scored entries are `{ scored: false, examMax }`
  - `rulesApplied[]`, `leitpunkte`, `errors` (at most 3, SCHEMA tags, `ruleCardId: null`), `remaining`
  - no pass verdict and no percentage.
- **Speaking response:** the same fields plus `passed: null`. `speaking_evaluations.score` holds the share of the scored maximum, for the old dashboards. The exact result is in `scores`.

## 2. How to run it

```bash
node scripts/course-v2/compile-rubrics.mjs          # registry + grammar-spine → _shared/course-v2/rubrics.json
node scripts/course-v2/compile-rubrics.mjs --check  # drift guard (exit 1 when stale)
node scripts/course-v2/compile.mjs <level>          # writes _shared/course-v2/<level>.banks.json (+ src/data/course-v2/<level>/)
node scripts/course-v2/compile.mjs --all --fixture --out <tmp>/out --banks-out <tmp>/banks   # the SCHEMA §15 fixture
COURSE_V2_DATA_DIR=<tmp>/banks node …               # point the graders at a scratch banks dir (copy rubrics.json in)
node --test tests/course-v2-ai.test.mjs tests/course-v2-entitlement.test.mjs tests/course-v2-completion.test.mjs
for f in netlify/functions/*.mjs netlify/functions/_shared/**/*.mjs; do node --check "$f"; done
```

**Tests**
- `tests/course-v2-ai.test.mjs` (48 tests):
  - KEY-01, EXM-08, the scoring plan including Aussprache and `appliesIf`, and the register-wrong/mixed caps
  - descriptors and the error policy in the prompt
  - the writing and speaking branches against the compiled fixture, with a fake Supabase and the real entitlement module
  - wiring pins, the `netlify.toml` line, and the `rubrics.json` drift guard.
- `tests/course-v2-entitlement.test.mjs` (26 tests): the access rule, the allowance, the degraded mode, and the config sync with `src/config/courseV2.js`.
- `tests/course-v2-completion.test.mjs`: completion.

**Verified on 2026-09-27**
- End-to-end: the fixture compiled to scratch, and `handleWritingV2` served `a21-u07-w` from disk through `COURSE_V2_DATA_DIR`: 200, 8.5 of 10 on `ga2-s2`, `exam_key = goethe_a2`.
- `npm run lint`: clean.
- `npx vite build`: builds.
- `node --check`: every function passes.

## 3. What the integration pass changed (seams between the two agents and the moving registry)

1. **The SPA did not build.**
   - `SubscriptionContext.jsx` and `LevelSubscriptionGuard.jsx` import `src/config/courseV2.js`, which did not exist.
   - Created it with the contract values. The entitlement test's client/server flag comparison now runs instead of being skipped.
2. **Aussprache was scored from a transcript.** BLUEPRINT §4.4 and SCHEMA §4.5 say it never is.
   - `grade.mjs` now leaves out every not-auto-scored criterion from the model, the prompt and the total: `scoredBy: 'notAutoScored'`, the interim `weight: 0`, or any `au`/`aussprache` criterion.
   - These criteria are returned as `{ scored: false }`. `rubric.examMax` carries the exam maximum.
   - Scored maximums: ga2-sp 20 of 25, tb1-m1 12 of 15, tb1-m2/m3 24 of 30, tb2-m* 21 of 25.
3. **Registry changes made during the build (Prüferin W2) broke the grader.**
   - The Goethe A2 Sprechen E-zero rule was removed. Test updated: an Aufgabenerfüllung of 0 no longer zeroes Sprache.
   - The telc B1 and B2 rules were renamed to `…-register-wrong-or-mixed`. Implemented: the cap now also fires when the text consistently uses the wrong address form for the task (from `address`, else from `register`), or ends a Sie letter with a friends' greeting. The old ids are gone, so `rules.mjs` again defines exactly the 16 ids the registry uses.
4. **The SCHEMA §4.5 fields were rejected by the checker, so `compile-rubrics` refused.** The fields are `method`, `examMax`, `scoredBy`, `descriptors`, `bands`, `errorPolicy`, plus the new `appliesIf`.
   - `scripts/course-v2/lib/schemas/rubric.mjs` accepts them, optional during the migration.
   - It also checks:
     - one descriptor per level for AI criteria
     - Aussprache must be `notAutoScored`
     - `method` and `modelId` agree (`modelId: null` is allowed for `method: deterministic`)
     - `examMax ≥ max`.
   - `modelFor()` honours `method: deterministic`.
5. **The grader now uses the new data.**
   - Descriptors (one line per level) and the band's `errorPolicy` (tags only flagged at that level: „senken keine Stufe") go into the system block.
   - A criterion with `appliesIf: 'targets'` drops out when the micro-output has no target, so `course-micro` is worth 4 instead of 5.
6. **The degraded allowance was wrong.** This is the mode before the migration.
   - It counted `writing_submissions` by the exact key, so a lane switch doubled the attempts.
   - It also counted rule-decided zeros (`model = 'deterministic'`), which cost no model call.
   - It now counts per slot, and only rows a model graded, exactly as the ledger does.
7. **v2 writing used up the exam-bank monthly limit.**
   - The legacy tier counts (Pro month, trial lifetime) counted every row.
   - They now exclude v2 keys with `not.match V2_TASK_KEY_PG_RE`. A test proves that no exam or `aNN-lNN` key matches.
   - The A1.1/A1.2 lifetime count keeps its `…l%` filter.
8. `incrementCourseUsage` recorded spoken micro-outputs as `speaking`. It now records them as `micro`.
9. The speaking reading "one attempt = one session, recorded at session start" is now written into `entitlement.mjs`, so the two tracks no longer contradict each other. `ENTITLEMENT.md` describes the degraded mode accurately.
10. The E0 fixture loader crashed on a reworded SCHEMA §15 heading (`ta2.json` "(excerpt;"). The marker is now a prefix; see §4 for what is still red there.

## 4. Still missing before launch

**Blocking a sale or a `COURSE_V2_LIVE` entry**
- **No level banks.** Only `rubrics.json` is in `_shared/course-v2/`.
  - Every v2 key answers `unknown task` until `compile.mjs <level>` writes `<level>.banks.json` from authored units (W3).
  - Commit the banks together with the units.
- **The migration is not applied** (`2026-10-01-course-v2.sql`).
  - Until it is, spoken v2 slots are gated by access only; there is no per-slot count for speaking.
  - Add the ledger row to `migrations/README.md` when you apply it.
- **Owner decision D1** (`V2_TRIAL_PRO_OPENS_PAID`, false on both sides): flip the client and server copies together.
  - Also pending: D7 (anonymous first-sentence scoring), D8 and FernUSG (`ENTITLEMENT.md` §6).
- **`rubrics.json` goes stale on every edit to the rubric registry or `grammar-spine.json`.** The W2 agents are still editing both, and the drift test fails each time.
  - `compile.mjs --all` (E0) or CI should run `compile-rubrics.mjs` with the same output path and `{ profiles, spineLabels }` shape.
  - Until then, rerun it after each registry edit.
- **The E0 schema suite is red, and that is not the server track.**
  - `tests/course-v2-schema.test.mjs` fails 8 tests, because SCHEMA §15 was rewritten on 2026-09-27 and the committed fixtures in `content/course-v2/fixtures/` no longer match it verbatim.
  - The schema owner or E0 has to re-sync the fixtures and the compiled-fixture expectations. After that, rerun `tests/course-v2-ai.test.mjs`, which reads the same fixture.
- **The rubric registry is only partly migrated to SCHEMA §4.5.**
  - tb1-*, course-micro and course-micro-sp carry `method`, `examMax`, `scoredBy` and descriptors.
  - ga2-*, sd1-* and tb2-* still use labels only, so the model grades them without our own descriptors.
  - Once every profile carries the fields, make them required in `lib/schemas/rubric.mjs`.
  - `appliesIf` needs its line in SCHEMA §4.5.

**Known limits, accepted for now**
- `method: 'deterministic'` profiles (sd1-s1 forms) return 400 `deterministic_task`. The player's items check forms.
  - `form-number-exact` is available as a pure rule for whoever grades forms.
  - A criterion-level `scoredBy: 'deterministic'` inside an AI profile is not computed yet. No profile uses it.
- `errors[].ruleCardId` is always null, because there is no errorTag → rule-card map yet. The player resolves the tag.
- v2 speaking sessions are stored with `mode: 'free'` because the `speaking_sessions.mode` CHECK is unknown. They are marked by `scenario.v = 2`, so admin views that group by mode count them as free.
- Calibration (CAL) is deferred: every profile has `calibration.status: 'pending'`, so every result is a *Richtwert*.
- The model pins in `defaults.mjs` are Sonnet 4.6 for full grading and Haiku 4.5 for micro-outputs. Changing one means a CAL re-run.
- The cache marker on the system block is probably inactive, because the prompts are below the minimum cacheable length.
- A legacy-style read-aloud id bypasses the v2 access check (signed-in user, capped at 60 clips a day). D7 decides the anonymous case.
- The compiler writes `manifest.json`; the contract text says `course.json`. `completion.js` accepts both.
- The SQL side of completion (course funnel, `weekly_truth_metrics()`) belongs to the PR that switches a level to v2.
